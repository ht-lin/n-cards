## 任务卡格式

每个任务卡包含：**角色**（BE 后端 / AND Android / OPS 运维 / PM 产品）、**预估**（人日）、**依赖**、**交付物**、**实现要点**（规格中容易做错的地方）、**验收标准**、**规格引用**。

编号约定：`T-0xx` = M0；`T-1xx/2xx/3xx/4xx` 中 **x00–x49 为后端**，**x50–x99 为 Android**。

## 全局约束（每个任务都适用，不再逐条重复）

1. **契约优先**（§13.1）：任何涉及 API 的任务，**必须先改 `docs/api/openapi.yaml`**，与双端实现在同一 PR 内合入。禁止自动生成契约。
2. **Definition of Done**（§13.8）：CI 全绿 + 契约同步 + 单测/集成测试 + 德英双语文案 + 无障碍检查 + （若涉及个人数据）更新 ROPA + （若涉及新端点）配置限流 + （若需运维介入）写 runbook + 低端真机（Android 8 / 2 GB RAM）验证。
3. **分支**（§13.2）：trunk-based，功能分支 ≤ 3 天，Conventional Commits，squash merge，未完成功能走 feature flag 合入 `main`。
4. **迁移**（§13.5）：只允许 expand–contract；禁止改列名/删列/一次性 `SET NOT NULL`；每个迁移必须有可用的 `down()`。
5. **范围纪律**（§1.3）：任何"顺手加一下"的需求若属于 OUT 清单（iOS、图片存储、邀请链接、邮箱邀请、editor 角色、所有权转让、商家目录、到期提醒、订阅、通讯录、Web、一次性副本分享）→ **一律拒绝**。

## 三个必须在 M1 前定死的语义（做错要返工整块）

| 语义 | 结论 | 出处 |
|---|---|---|
| 谁能写卡 | **只有 owner**。viewer 除 `placement` 外无任何上行写入 | ADR-01 / §3.5 |
| `sort_order` / `is_pinned` 存哪 | 在 `card_members` 上（**每成员私有**），不在 `cards` 上 | §5.2 |
| `change_log.audience` | `card` 走广播（全体成员）；`card_member` 走点对点（**仅 owner + 当事人**）。删除类记录的 audience 取**删除前快照** | §5.2 |

> 第 3 条是全项目最容易写错、且错了会**在数据库层面泄露 viewer 名单**（前端无法补救）的地方，见 T-201。
