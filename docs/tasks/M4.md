## T-401 audit_log 与 AuditLogger

**预估** 1 人日 · **依赖** T-004

**交付物** `audit_log` 表 + `Compliance` 模块的 `AuditLogger`，接入各模块的关键动作。

**必须记录的 action**（v1.1 清单）：`login_success` / `login_failed` / `session_revoked` / `username_set` / `card_shared` / `share_accepted` / `share_declined` / `member_removed` / `member_left` / `shares_revoked_by_unfriend` / `friend_removed` / `friend_blocked` / `account_deletion_requested` / `account_hard_deleted` / `data_exported` / `key_rotated`。（已移除 `ownership_transferred`。）

**实现要点**
- `metadata` 是 JSONB，**不得**包含码值、邮箱明文、备注内容。
- 保留期 **12 个月**（GDPR Art. 6(1)(f) 正当利益）。
- 硬删除后该用户的行保留 action + 时间 + **匿名化 id**（`actor_user_id` 替换为随机化假名，不可再关联到自然人）。

**验收标准** 单测断言 metadata 不含敏感字段；每个 action 至少有一处调用点。

## T-402 数据导出（Art. 15/20）

**预估** 2 人日 · **依赖** T-401, T-305

**交付物** `POST /v1/me/export` → `202 {job_id}`（异步）；`GET /v1/me/export/{job_id}` → 状态 / 下载链接。ZIP 内含 `cards.json`、`friends.json`、`shares.json`、`devices.json`、`audit.json`、`README.txt`。

**实现要点**
- **码值必须是解密后的明文**——这是用户自己的数据，Art. 20 要求"结构化、通用、机器可读"。
- 下载令牌**一次性、24 小时有效、绑定会话**，通过 **App 内下载**（**不通过邮件发链接**）。
- **导出也必须遵守成员可见性（C11）**：
  - 作为 owner 的卡 → 列出全部 viewer 的 username；
  - 作为 viewer 的卡 → **只列 owner 与自己**，不得出现其他 viewer；
  - `friends.json` **只含 username**，不含对方邮箱等任何其他字段。
- **导出是最容易绕过权限检查的地方**——它通常由独立批处理直接查库，不复用 API 的裁剪逻辑。**必须**让 `DataExporter` 复用与 `GET /v1/cards/{id}/members` 相同的查询，或为其单独写一条断言测试。
- SLA ≤ 24 小时（目标 < 5 分钟）；过期导出包由 Scheduler 清理。

**验收标准** 集成测试断言 viewer 身份导出的 `shares.json` 中不出现第三方 viewer；下载令牌用过一次即失效。

**规格引用** §8.4

## T-403 账号删除（Art. 17）

**预估** 2.5 人日 · **依赖** T-401, T-303

**交付物** `GET /v1/me/deletion/preview`、`POST /v1/me/deletion` → `200 {scheduled_for}`、`DELETE /v1/me/deletion`（取消）+ 每日 `PurgeDeletedAccounts` 任务。

**实现要点 — 语义（C8：一律不转让）**
- 用户拥有的卡 → **全部硬删除**，无论是否有 viewer。对每位 viewer 表现为成员墓碑 + 卡墓碑，其本地行被物理清除。
- 用户作为 viewer 参与的卡 → 仅移除成员关系（对 owner 是普通"成员离开"），**卡本身不受影响**。
- 好友关系 → 双向硬删除，对方列表中该用户直接消失（**不留"已注销用户"占位**，避免残留个人数据）。
- 待处理的共享邀请与好友请求 → 一并硬删除。
- 30 天宽限期（`status = pending_deletion`），期间**任意成功登录即自动取消删除**；宽限期内该用户对所有卡不可见、不接收推送。**宽限期内共享关系保持不变**（删除可撤销，提前撤销共享会让"取消删除"无法完整还原）。

**实现要点 — 硬删除顺序（步骤 0 与 7 的顺序是关键）**
```
0. 快照 audience：收集该用户所拥有的每张卡的当前成员列表   ← 必须最先做
1. INSERT change_log：每张自有卡的 card 墓碑（audience = 步骤 0 的快照）
                      每条成员关系的 card_member 墓碑
2. DELETE cards WHERE owner_id = :user   （card_members 经 ON DELETE CASCADE 清除）
3. DELETE card_members WHERE user_id = :user    -- 作为 viewer 的关系
4. DELETE friendships（双向）
5. DELETE share_invitations（作为 inviter 或 invitee 的全部行）
6. DELETE users, devices, sessions, otp_challenges（按 email_hash）
7. UPDATE change_log SET audience = array_remove(audience, :user)
   → DELETE FROM change_log WHERE audience = '{}'
   -- 步骤 1 写入的墓碑其 audience 含其他用户，不会被此步清空 ← 这正是 1 必须早于 7 的原因
8. audit_log：保留 action + 时间 + 匿名化假名 id
```

**删除确认页（`preview` 端点）必须明示影响面**：`{owned_cards_count, shared_cards_count, affected_friends_count, cards_i_will_lose_count}` → 「你拥有的 N 张卡将被永久删除，其中 M 张正共享给 K 位好友，他们将同时失去这些卡。**卡片不会转让给任何人。**」

**username 删除后可复用**：随 `users` 行物删，可被新用户重新注册。一期**接受该风险但不放大**——好友关系已双向硬删，冒名者无法继承任何既有关系。**不实现** username 保留期（与 Art.17"彻底删除"直觉冲突，且攻击者可以等）。

**验收标准（§13.4-2 删号完整性测试）** 建立含共享、好友、邀请、设备的完整用户 → 硬删 → **逐表断言无残留**；**并断言 viewer 侧确实收到卡墓碑**（不只是数据库干净）；断言 `friend_invite_links` 表不存在（若迁移中仍有残留 DDL 属于遗漏）。

**规格引用** §1.4 J5、§3.7、§6.2、§8.4、§13.4

## T-404 密钥轮换与 rewrap

**预估** 1 人日 · **依赖** T-005

**交付物** Messenger 任务 `RewrapCardSecrets` + `docs/runbooks/key-rotation.md`。

**轮换流程**
1. `vault write -f transit/keys/ncards-card/rotate` → 产生 v2
2. 新写入自动用 v2
3. `RewrapCardSecrets` 分批调用 Transit `rewrap`（**无需解密到应用侧**），更新密文列
4. 全部完成后 `min_decryption_version` 提升到 2
5. 记录 `audit_log(action='key_rotated')`

**实现要点** `transit/ncards-hmac`（pepper）**不轮换**——轮换会使全部 hash 失效，需专门迁移流程。JWT 签名密钥 6 个月轮换，双密钥重叠期 24h。

**验收标准** 在 staging 完整演练一次轮换，rewrap 后旧密文仍可解密且新密文用 v2。

**规格引用** §5.3

**验收标准** 故意触发一条 P1 告警能收到通知；日志中检索 `barcode_value` 无明文命中。

## T-453 性能与 Macrobenchmark 达标

**预估** 1 人日 · **依赖** T-254

**性能预算（全部需实测达标）**

| 指标 | 目标 |
|---|---|
| Widget 点击 → 条码完全渲染 | P95 ≤ 800 ms（冷启动 ≤ 1.8 s） |
| 钱包列表首帧（温启动） | P95 ≤ 400 ms |
| 列表滚动（200 张卡） | P99 帧耗时 < 16.6 ms |
| APK 下载大小 | ≤ 20 MB |
